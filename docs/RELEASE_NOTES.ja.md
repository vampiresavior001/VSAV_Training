## v11.7.23.1

### Meaty Timing：相手の反撃と、キュービーの起き上がり

- 相手の攻撃が先に当たった復帰（無敵技のリバーサルなど）は、相手の側を付けて
  `Wake-up  Reversal +4t  P2 Hit First` と出るようにしました。これまでは、自分の攻撃判定が
  出ていると、相手の攻撃が当たった Tick を自分の重ねとして、持続の Tick まで出していました。
  どちらが当てたかは、ゲーム自身の打撃の判定から取ります。開発側の実機ログでは、モリガンの
  シャドウブレイドのリバーサルを 2 回とも見分けました
- 当てたのが飛び道具なら、本体の攻撃判定が出ていても `Active -` です
- リバーサルTickの無いキュービーの起き上がりも測るようにしました。必殺技も通常技も出せる
  最初のTickから数え、`Wake-up  Actionable +Nt` と出ます。マニュアルの
  [キュービーの起き上がり](PLAYER_MANUAL.ja.md#meaty-timing-qbee)を見てください

### Frame Meter

- やられ中・ガード硬直中・ダウン中・起き上がり中は、地上でも空中でも、無敵の白も投げ無敵の
  縞も描かないようにしました。白と縞は「当たるはずの所で当たらない」ことを示すもので、
  これらの間は守られているのが当然です。これまでは起き上がりの最後、リバーサルTickの
  手前まで白が続いていました
- キュービーの起き上がりの最後（首振り）は、動ける最初のTick（`Actionable +0t`）から白で
  示します。そこから 2～3 Tick は、通常の打撃を受け付けません
- ステートを読み込んだとき、前後の記録をつなげず、前後を比べた偽のリバーサルの印や投げも
  描かないようにしました。画面の記録はそのまま読め、次の動きで新しい記録が始まります

### 設定ファイル

- 閉じ括弧の後に文字が続くファイルや、設定ではなく配列が入ったファイルを、読めないファイル
  として扱うようにしました。パスを表示し、FBNeo を再起動するまで保存しません。これまでは
  一部だけ読み込まれ、その上に保存されていました

### マニュアル

- 相手の行動の読みに合わせて重ねるタイミングを選ぶ方法と、`+0t`～`+6t` の目安
  （[11.2](PLAYER_MANUAL.ja.md#meaty-timing-strategy)）。起き攻めの練習レシピに Meaty Timing を
  足しました（[10.B](PLAYER_MANUAL.ja.md#wakeup-pressure-drill)）
- GC のコツに、1P 側の入力が遅いときのアケコンの置き位置
- Frame Meter：マスの数字は、上端が灰色の Tick を除いて数えること

## v11.7.23

### 新機能：Mute Idle Sounds

- `Game > Mute Idle Sounds`（初期値はOFF）で、待機中のキャラクターが繰り返す声・効果音を
  止めます。対象はガロン、ダークガロン、ジェダ、ビクトル、バレッタ（しゃがみ待機）です。
  待機の動きはそのままで、攻撃・ガード・被弾の音とBGMは残ります。P1・P2の両方が対象です。
  マニュアルの[12. 表示とゲーム設定を調整する](PLAYER_MANUAL.ja.md#12-options)を見てください

### 新機能：Meaty Timing

- `Trainer > Tick Data` の下に `Show Meaty Timing`（初期値はON。保存済みのOFFは
  そのまま）を足しました。起き上がり・ガード後・やられ後・空中やられ復帰で、相手の
  リバーサルTickから何Tick後に、持続の何Tick目で攻撃が当たったかを、Tick Dataの行と
  Action Timelineの間に1行で出します：`Wake-up  Reversal +0t  Active 3t`
- リバーサルTickは、相手が再び動ける最初のTickで、ガードと必殺技だけができるTickです
  （Frame Meterのマゼンタの線）。+0～+30Tickの最初のヒットまたはガードを記録します。
  `Active 2:3t` は2つ目の持続の3Tick目、`Active -` は飛び道具か投げです
- 連係の成否は判定しません。マニュアルの[11.2 Tick Data](PLAYER_MANUAL.ja.md#meaty-timing)を
  見てください

### Frame Meter：表示の設定で数値が変わらないように

- **上端の灰色の線：ヒットストップで止まっていたTick。** そのキャラの数値とマスの数字に
  数えません。デミトリ近距離LPのガードは、`Show P1 Inputs` のON・OFFどちらでも
  Startup 4 / Total 13 / Recovery 7 です。防御側の黄の数字は、Tick DataのHitstunと
  一致するようになりました（このLPで13、小Kのヒットで14）。実機で確かめました
- **上端のマゼンタの線：リバーサルフレーム。** 起き上がり・ガード後・やられ後・空中やられ復帰で、
  動ける最初のTickです。このTickにできるのはガードと必殺技だけです。P1・P2とも。実機で、
  印のTickから必殺技、その次のTickからダッシュが出ることを確かめました。キュービーの
  起き上がりには付きません
- `Log Hitstop Frames` をなくしました。ヒットストップ中のTickとAGの受付は、
  `Show P1 Inputs` がONのときに並べます。ヒットストップ中の入力も受け付けられるので、
  いつ入力したかを見るためです。AGの成立は常に表示します
- 投げ無敵は、発生・攻撃判定・戻りを置き換えるのをやめ、マスの下半分に赤と白の縞で
  重ねて描くようにしました。`Show Throw Invulnerability` で数値が変わらなくなり、
  初期値をONにしました（保存済みの設定はそのまま）
- `Show Movement Data` は `Include Jumps / Dashes` になり、初期値がONになりました
  （保存済みの設定はそのまま）
- マスの数字は、同じ色が5マス以上続いたときに出します（以前は6マス）
- 持続のすぐあとに動ける技の硬直が0になっていました。動けるようになるTickを硬直に
  数え、表とTick Dataに合わせました（デミトリのミッドナイトプレジャーの空振りで
  2 / 29 / 1、Total 31）
- 無敵は、白いマスではなく、マスの下半分を白で重ねて描くようにしました。発生の途中で
  無敵が切れる技も、どこで切れるかが分かり、Startupもそこから数え直さなくなりました。
  基準はヒットボックス表示と同じで、ビシャモンの切り捨て御免のように、やられ判定が
  消えることで無敵になる技も出ます。白いマスに隠れていたダークフォースの発動は、
  緑（発生）で描きます
- 投げを表示するようにしました。投げには攻撃判定がないため、これまでは投げ全体が発生
  （緑）になり、投げられた側は何もしていないマスになっていました。ゲームが掴みを試す
  Tick（空振りも含む）と、相手を掴んだTickを赤にし、投げのStartupはそこまでになります。
  投げられている間は黄です
- マニュアルの[11.6 Frame Meter](PLAYER_MANUAL.ja.md#frame-meter)を見てください（画像を撮り直しました）

### 設定ファイルを `scripts` の外へ

- 設定ファイル（設定・Action Steps・Action Patterns）を、FBNeoフォルダーの
  `training_data/training_settings.json` に移しました。更新で置き換わる `scripts` の
  外です。形式と中身は変わりません
- 最初の起動で、既存の `scripts/training_settings.json` を自動でそこへコピーします。
  両方ある場合は `training_data` の方を使います。元のファイルは控えとしてその場に
  残りますが、以後は更新されません
- 記録は引き続き `scripts/macro` にあります。`training_data` と `scripts/macro` の
  両方をバックアップしてください
- 保存は一時ファイルに書いて確かめてから置き換えるようにしました。保存に失敗しても、
  ファイルが空になることはありません
- 設定ファイルが読めないときは、画面上部に赤い表示でそのパスを出します。FBNeoを
  再起動するまで何も保存せず、ファイルも上書きしません。マニュアルの
  [13. 保存・バックアップ・更新](PLAYER_MANUAL.ja.md#13-save)を見てください

### 起動バッチ：配置先のパスに空白があっても起動

- `run_vsav_training.bat` は、ステートとスクリプトを自分のフォルダーからの相対パスで
  FBNeoに渡すようになりました。空白を含むパス（`C:\Fight cade\...` など）でも
  起動します。日本語を含むパスは、引き続き問題が起きる場合があります
- コマンドプロンプトから実行しても、そのウィンドウが閉じなくなりました

### 修正：入力バーに負の数が出る

- スクリプトを起動した直後、`Show Scrolling Input` のいちばん古い列に、-25593のような
  大きな負の数が出ることがありました。最初のゲームTickより前に記録した列を、別の時計で
  数えていたためです。その列は捨て、負の数は描かないようにしました

### 修正：Tick Data の投げ

- コマンド投げのStartupが、掴みではなく、コマンドが成立したときにゲームが確かめる
  間合いの判定で終わっていました。ダッシュからデミトリのネガティブストーレンを出すと
  Startup 1・持続2回になっていましたが、5Tick後の掴みで数えるようにしました
  （フレーム表の発生6・持続1と同じ）
- Tick Dataは、ゲームが掴みを試すTickを、地上・空中・やられ中の相手のどれでも数える
  ようになりました。空中投げはこれまで測れていませんでした

### 修正：Pharaoh Salvation と Pharaoh Decoration

- アナカリスの2つの技の技IDが、互いに逆になっていました。Character Specific Reversal で
  `P. Salvation` を選ぶと Pharaoh Decoration の技IDを書き込み、Tick Data の技名も
  逆でした。Action Steps の入力は元から正しく、変えていません

## v11.7.21.2

### Button Wait と、ボタンの Random Delay

- `Guard Action Delay (Ticks)` を `Button Wait` に改名しました。Reversal / Counter Attack -
  Specified ではモーションの後でボタンを押すまでの待ちで、モーションは最速のまま出ます。
  Push Block と PB Recording では押し始めるまでの待ちです。保存した値はそのまま使えます
- 上限を60 Tickにしました。これまではメニューで50まで選べましたが、31〜50は30として
  動いていました
- その下に字下げした `Random Delay` の行を足しました（ゲームのTickで0〜60、0は使わない）。
  反撃やカウンタのたびに0から設定値までの乱数を引き、Button Waitに足すので、ダッシュ攻撃や
  ジャンプ攻撃を押す時期が毎回変わります。Auto にも足せます。`Forward Dash`＋`HP`、Auto、
  `0-5` で、最速のダッシュ攻撃が5 Tickの幅でばらつきます
- 遅すぎたときはゲームが決めます。必殺技はコマンドが14〜19 Tickしか保持されないので通常技に
  なり、ダッシュやジャンプが終わった後ではダッシュ攻撃・ジャンプ攻撃になりません。待っている
  間も方向は入れたままなので、ジャンプは着地後にもう一度跳ぶことがあります

### 修正：被弾後のカウンタで、待ちが長いとボタンを 2 回押していた

- ボタンがダミーの動けるようになってから約 12 Tick より後になると、後片付けの処理が本来の押しより
  先に入力の最後をボタンごと出していました。ダッシュキャンセル小Pが、ダッシュ小Pと立ち小Pの 2 回に
  なっていました。本来の押しを待つようにしました。以前の版でも Guard Action Delay を長くすると
  同じことが起きていたはずです（コードからの推定で、以前の版では確かめていません）

### マニュアル

- Random Start Wait と Random Delay を、関係する所すべてに書きました（ティックの表、ループ、
  パターンのファイル、困ったとき、最速を前提にした手順）

## v11.7.21.1

### Random Delay — ステップの Wait に乱数を上乗せする

- Action Steps の各ステップに、`Wait` の下に字下げした `Random Delay` の行を足しました（ゲームの
  Tickで0〜60、0は使わない）。ステップが出るたびに、0から設定値までの乱数を引き直し、Waitで決まる
  タイミングに足します
- Wait の種類を問いません。数値、After、Auto、Landing、Chain／Cancel 系のどれにも上乗せできます。
  Chain や Cancel では値を大きくすると受付を外れ、人間がつなぎ損ねたときのように単発の技として出ます
- 使い方の例：最速の入力に `0-5` を足して人間のぶれを再現する、大きい値で固めの間隔を毎回変える
- 一覧ではWaitの後ろに `+6t +0-5t` のように表示します。1ステップ目の値は `Random Start Wait` と合わせて
  引きます。Action Patterns の書き出し・取り込みにも入ります（古い版で取り込むと、この値だけ無視されます）

## v11.7.21

### Random Start Wait — ダミーの行動の前に乱数の待ちを入れる

- 新しい設定 `Random Start Wait` を足しました。単位はゲームのTickで0〜60です。Dummyタブの
  `Random Guard Action %` の下と、Recordingタブの `Loop Interval (Frames)` の下にあり、2つの行は
  同じ設定です
- ダミーが自分から行動を始めるたびに、0から設定値までの乱数を引き直し、その分だけ待ってから
  始めます。対象はReversalとCounter Attackのすべての種類、`Loop Steps` の各周（`Loop Wait` の後）、
  記録の再生のすべて（`Looped Playback` の各回は `Loop Interval` の後）です
- `0` は使わない設定で、従来どおり最速です。防御（ガード、AG（Push Block）、GC、投げ抜け）と、

## v11.7.16

### 空中ガードの隙間を見せる `Show Air Guard Gaps` を追加しました

`Trainer` タブの **`Show Air Guard Gaps`** を `yes` にすると、空中チェーンをガード
したときに、**割り込める隙間がどれだけあったか**と、**どこで押してどうなったか**を

AirGap                               Gap  Press>Hit
Jump > 6t J.LP(5t)                        PreJump(3t) > Guard 9t

## v11.7.12

### ガードキャンセルのコマンドを、ゲームが受け付けた順に出すようにしました

**GC Command Trace** は、ガードキャンセルに向かう途中で**ゲームが実際に受け付けた**
入力を、ティックと一緒に並べます。**押したもの全部ではありません。**

```
GC Command Trace
  Guard
  ->        3t
  v         1t
  v>        1t
  [LP]      7t
  Success  12t
```

- **矢印とボタンは入力ビューアと同じ絵**です。下のバーと見比べられます
- **数字は 1 つ上の入力からの経過。**最速なら各方向が `1t`、最後のレバーと
  ボタンが同じティックなら `0t` です
- **入力どうしが `12t` 以上なら琥珀色。**必殺技の入力どうしの猶予は乱数で、
  **`11t` までは普通に出る値**です。それを超えて通ったものは**引きが良かっただけ**
  で、同じ入力が次は落ちます。出てはいるので**エラーではなく警告**です。
  **ガードや期限切れを相手にした数字には付きません**（`Guard` の行と、その下で
  数え直した最初の数字）— どちらも端が入力ではないので、この読み方が
  成り立ちません
- **括弧が付くのは `Guard` の行だけ。**ガードは入力ではないので、その数字だけ
  括弧で囲みます。`Guard (8t)` は「最後の入力から 8 ティック後にガード」、
  一度切れた後なら「切れてから 8 ティック後にガード」です。
  **ガードから測った数字に括弧は付きません** — ガードがそのまま数え直しの
  起点になるので、その数字は流れの一部です
- **`Success` だけは Guard から。**入力ビューアの `SUCCESS` と同じ数字です

**描くのはガードが来てから**です。ガードより前に入れ始めたぶんも遡って出るので、
**コマンドを先に入れる練習にも使えます。**

**失敗の理由が区別できます。**

- **`GC Expired`** — 受付の 14 ティックが切れた。**コマンドは間に合っている**
- **`Cmd Expired`** — コマンドが繋がらなかった。**中立で切れたか、次の入力が遅い**

**ガードの受付が開いている間にコマンドが切れて入れ直したときは、同じガードの
続きとして出します。**受付はコマンド 1 回ぶんより長いので、落としてから入れ直して
同じガードでキャンセルが成立します。

**コマンドが死んだ直後のガードも、同じ流れとして続けて出します**（16 ティック
以内）。16 は 1 入力の猶予の 1 つ外側です。「遅すぎた入力」と「その直後のガード」は
いちばん見たい組み合わせなので、捨てずに繋ぎます。死んだ印は行として残るので、
上の行が別の試行のものだと分かります。

```
GC Command Trace
  ->
  v            4t
  Cmd Expired 15t     <- 最後の入力から、何ティックで切れたか
  Guard       (2t)    <- 切れてから、何ティックでガードしたか
  ->           3t     <- ガードから、何ティックで入れ始めたか
  v            4t
```

**`Cmd Expired` で数え直します。**そこから下は 2 回目の試行なので、1 回目の入力から
数えると 3 つの区間を足した数字になり、1 つの待ちのように見えてしまいます。

**受付が閉じた後の入れ直しは、新しい trace として最初から数えます。**どの数字も
2 回ぶんの待ちを足した値にはなりません。

`Trainer` タブの **`Show GC Command Trace`**（既定 OFF）。

### バレッタを弱パンチで選ぶと、2P にレバーが渡らない不具合を直しました

アーケードスティック 1 本で 2P のキャラを選ぶ機能が、**バレッタを LP で決定した
ときだけ**動きませんでした。**両方が揃ったときだけ**なので、出たり出なかったり
していたものです。

ツールが見ていた値が、この組み合わせでは全部 0 になっていました。キャラ番号は
**バレッタが 0**、決定に使ったボタンの番号は **LP が 0** です。キャラは正しく
選ばれていて、**こちらが気付けていませんでした。**

### キャラ専用の表示に、自前のスイッチを付けました

オルバスの `Direct Scissors` とアナカリスの `Ate Projectile` が、**何の説明も無く**
画面に出ていました。`Display` タブの **`Show Character Specific`**（既定 OFF）に

ダミーの Action Steps (ステップ列) を**名前を付けて複数保存し、選んで使える**
ようになりました。ライブラリは**キャラ別**で、対象は Reversal です。

`Trainer` -> `Guard Action Type` に **`Reversal - Action Patterns`** が付きます。

- 一覧の `[x]` が付いたパターンが走ります
- **チェックの数がそのまま再生モードになります。** 1 つなら毎回それ、
  複数なら**その中から周ごとにランダム**。サスカッチの
  「ショートダッシュ / ロングダッシュ / 下段」を 3 本チェックして
  ループ再生する、という使い方ができます
- 一覧では **MP** でチェックの付け替え。New / 複製 / 並び替え / 削除も
  行えます
- **New** で空から作るほか、**Add from current Steps** で今の Action Steps を
  まるごと取り込めます。編集は既存の Action Steps エディタそのまま
  (Edit で開きます)
- **Export to a File / Import from a File** で JSON の 1 ファイルに書き出し・
  読み込みができます。**インポートは追加で、既存は置き換えません。**
  練習内容をそのまま人に渡せます

名前の入力だけは Windows の入力窓 (PowerShell) を使い、窓が開いているあいだ
エミュレータは一時的に止まります。

### 裏回りの最中のダッシュが逆走しないように

キャラが交錯して向きが変わる最中のダッシュで、**2 タップが画面上で逆向きと
して出る**ことがありました。左右の補正は 2 系統あって読むバイトが違うため
です (ROM で確認)。生の方向だけでできている列 (ダッシュ・歩き) を向きの
バイトで解決し、振り向くあいだはダッシュのタップを待つようにしました。
同じ修正で、メニューを開いているあいだもダミーの入力が届き続ける穴を
塞ぎました。

### 起き上がりのダッシュが、裏回りのダウンでも出るように

Guard Action のリバーサルでダッシュを設定しているとき、**ダウン中に相手と
逆向きだったダウン**では起き上がりのダッシュが出ず、設定のボタンだけが
単独の通常技になっていました。free の瞬間にダミーが振り向くため、ダッシュの
2 番目のタップが逆向きに出ていたのが原因です。

振り向きの前後で押しの向きを追いかけるようにしました。裏回りのダウンでも
起き上がりの瞬間 (free+0/+1) にダッシュが出ます。

実測: 修正前 15 ウェイクアップ全部が失敗 → 修正後 35 ウェイクアップ全部が
ダッシュ。

### Action Steps の After / Landing も調整

- **After** は地上ダッシュのとき、着地するまで入力を出しません。
  空中ダッシュと地上ダッシュは入力が同じなので、実行時に区別します
- **Landing** の期限は、着地予測が出ているあいだ予測に従います。
  以前は期限だけが予測より早く開き、押しが空中に落ちて着地予測が
  使われないことがありました (13 回中 11 回)
- 失敗したダッシュのあとに立ち通常技が残ったとき、その技の硬直明けで
  次のステップへ進むようになりました (以前は Landing 待ちのまま
  止まることがありました)

**既定の動きは変わっていません。** 触らなければ今までと同じです。

## v11.7.3

### `Loop Wait` に `Auto (Landing)` を足しました

これまでの `Auto (After)` は、**ダミーが動けるようになってから入力を開始します。**
ダッシュのように入力が続くコマンドは、その助走の分だけ必ず遅れます (ダッシュで
3 ティック)。ガードの練習には向いていますが、最速ではありません。

**`Auto (Landing)` は、着地を予測してコマンドを先行入力します。** 最後の入力が
接地したティックちょうどに乗るので、着地後の最速行動をループで回せます。

ステップ側の `Auto (Landing)` は前からありましたが、**ループの再開には使えません
でした。** そこが埋まりました。

### ジェダの永久が、そのまま再現できます

デミトリ・ビシャモンに対する永久が、**`Loop Wait` を数値で合わせ込まなくても**
出ます。

```
Dummy タブ
  Guard Action Type      : Reversal - Action Steps
  Guard Action Frequency : 100%
  P2 Random Guard %      : 100%
  Guard                  : Stand Block
  Loop Steps             : yes
  Loop Wait              : Auto (Landing)

Reversal Action Steps : Jedah : 2 steps
  1  Auto (Fastest)  Dash   : Forward
  2  Auto (10)       Attack : Forward + HP
```

### 直したもの

**ダッシュ攻撃から着地ダッシュへ繋ぐとき、技によってコマンドが出ませんでした。**
発生の遅い技 (ダッシュ大 P / 大 K など) ほど起きやすく、小技なら問題ないという
形で症状が分かれていました。

ヒットストップが入力の配送と重なることが原因で、**重なり方によって別々の壊れ方を
していました。** 3 種類とも直しています。

- ヒットストップ中のティックも「入力した」と数えていました。ゲームはヒットストップ
  中の押しを受け取らないので、**実際には入っていない入力を入ったことにして次へ
  進んでいました。**
- ニュートラル (レバーを離す区間) でも待つようにしていました。**待っても得るものが
  無く、コマンドの受付時間を食うだけ**でした。
- ヒットストップが長いと、待っても受付時間を超えてしまいます。**その場合はコマンドを
  頭から入れ直す**ようにしました。

### 分かっているが直していないもの

**ガロン・フェリシアは、着地モーションをダッシュでキャンセルできません。** 上の
手順でも最速にはなりません。ゲーム側の仕様で、**人間が操作しても同じ**です。

## v11.6.2

### 直したもの

**プッシュブロックが出ないことがありました。**`Guard` を `Push Block (All ...)` に
しても、ガード自体が `P2 Random Guard %` に従います。ところがその行は
`Stand Block` と `All Guard` のときしか出ておらず、**プッシュブロックでは見えない
のに効いていました。**既定が `None` なので、触ったことがなければガードせず、

行を隠しても依存は消えないので、**値が読まれるときは行が出る**ようにしました。

**位置ショートカット (Lua Hotkey 2) で、真横の 2 つが効きませんでした。**
レバーを左右に倒して押すと何も起きず、下+左と下+右だけが効く状態でした。

「動ける状態か」の判定が `$06 == 0x00` だけだったためです。**歩きは `$06 = 0x04`**
で、このショートカットはレバーを倒しながら押すもの — **左右に倒せばキャラクターは
歩くので、頼む行為そのものが条件を壊していました。**しゃがみは `0x00` のままなので
斜めだけが通っていました。歩きも通すようにしました。

あわせて、**キーを押しっぱなしにしたときに 1 回だけ効く**ようにしました。ホットキーは
押している間くり返し呼ばれるので、配置を何度も組み直していました。

- `Auto (Rapid Fire)` — 連打キャンセル (小攻撃の後ろにだけ出ます)
- `Auto (Landing)` — 着地した瞬間
- `Auto (After)` — 前の技が終わったところ

数字でティック数を指定することもできます。ループもあります。

**必殺技はチートで出すのではなく、コマンドを入力して出しています。**チートで
起きていた変な現象は起きません。

タメ技のために**レバーの Hold** を付けました。Hold を入れたステップの間は方向が
入りっぱなしになります。

**Show Step Wait Ticks** (Display) — 各ステップが実際に何ティック待ったかが出ます。

```
Step.1 Act:3 / Step.2 Wait:13 Act:1 / Loop Wait:11 / Step.1 Act:3
```

**Show P2 Inputs** (Display) — 画面右端のダミーの入力アイコンを消せます。

### 変更

**Tech Throws を確率にしました。**`None` / `25%` / `50%` / `75%` / `100%` の
5 段です。抽選は **1 回の投げにつき 1 回だけ**振ります (毎フレーム振ると、抜け
入力がどれか 1 フレームに乗れば通ってしまい、50% でも実質 100% になります)。
以前オンだった設定は `100%` になります。

### 直したもの

**メニューを開くと、走行中の Action Steps を終了するようにしました。**開いても
ゲームは止まらないので裏で走り続けていて、レバーが入りっぱなしになる・編集中に
ダミーが勝手に動く・ループが前の内容のまま回り続ける、といったことが起きて
いました。閉じても勝手には回り始めません — ダミーを 1 回ガードさせるか殴ると、
編集後の新しいリストで動き始めます。

## v11.4.2

### 変更

**ループ再生の待ち時間を Before と After に分けました。**

親の行は `Loop Interval (Frames) : (Before/After)` で今の値を出します。右か LP で
子メニューが開き、**レバーだけで操作できます** — 左で減り、右で増え、上下で行を
移り、一番下の `Back` で戻ります。MP で 0 に戻せるのは今までどおりです。

- **After** は前の周が終わってダミーが動けるようになってから数える待ちです。
  今までの Loop Interval と同じ位置なので、**保存していた値は自動で After に
  引き継がれます。**
- **Before** は距離を戻したあと、次の周が出るまでの待ちです。

待ちが 1 か所しかないと、「距離を戻す前に間を置く」と「戻してから間を置く」を
区別できませんでした。`Reset Distance Each Loop` でワープしてから一拍おきたい、
という使い方ができます。

**メニューを閉じた直後、リピート再生が 30 フレーム止まるようにしました。**

閉じた瞬間に次の周が飛んでくると構える間がないためです。止まっている間は記録の
入力も出ません。再開は同じ記録位置からで、飛ばした分を取り戻す動きはしません。
単発の再生には影響しません。

**保存メニューの `Play again` は、ダミーが動き終わるまで選べないようにしました。**

記録は入力が途切れた時点で終わりますが、キャラクターはまだ技を出し切って
いません。そこで `Play again` を押すと、**動けないダミーに向けて再生し直す**
ことになり、状況が再現されませんでした。動いている間は灰色で `(still moving)`
と表示され、終われば押せます。

**待つのはこの 1 つだけです。**`Save to this slot` と `Record again` は
ダミーが何をしていても即座に応答します。次をすぐ記録したいときに待たされません。

あわせて、再生中に押していたボタンがそのまま選択の答えにならないように
しています。

**記録ウィザード中は `Lua Hotkey 1`（中止）だけが効くようにしました。**

`Lua 3`（ループ切替）と `Lua 4`（キャラクターセレクトへ戻る）は、再生や記録の
最中に割り込んで状態を壊すためです。中止だけは残しています。

**`Play Recording` は、右を押している間に何度も反応しないようにしました。**

右は押しっぱなしで連続入力になるため、再生の開始と停止を繰り返していました。
一度の押下で一度だけ反応します。

**キャラクターポジションの変更で、画面が一緒に動くようになりました。**

これまでカメラは自力で追いかけていたので、移動が終わっても画面だけ遅れて
追いついていました。移動そのものも少し速くなっています。

### 修正

**記録ウィザードの確認再生と `Reset Distance Each Loop` で、位置と画面が
記録したときに戻るようになりました。**

これまでは 2 人の位置は戻っても**画面のスクロール位置が戻り切らず**、さらに
画面の外に置かれたキャラクターが引き戻されることがありました。ガロンの K 投げ
のように 2 人が入れ替わって大きく動く記録で特に目立ちました。

**v11.3.x で保存した設定が正しく引き継がれるようになりました。**

移行が行われず、**選んでいたリバーサルが隣の項目にずれたり**、ループ間隔の
保存値が失われることがありました。

**複数ヒットするガードのあとでも、リバーサルとカウンターアクションの必殺技が
出るようになりました。**

小技の連打キャンセルなどで 2 ヒット目をガードしたとき、入力が積み直されず何も
出ないことがありました。

**`Knockdown Logger` をオフにしたときに、診断用の記録が完全に止まるように
なりました。**

オフでも一部が動き続けていたため、`reversal_logs` にファイルが書かれ、動作も
重くなっていました。

## v11.4

v11.3.1 からの変更です。

### 新機能

**記録ウィザード**

ダミーの記録を案内付きで行えます。Recording タブの `Recording Wizard` から始めます。

スロットを選ぶと操作がダミー側に切り替わり、動かし始めたところから記録が始まります。手を止めて2秒で自動終了し、そのまま記録したものを一度再生して見せます。確認してから保存、気に入らなければ記録し直し、もう一度再生、が選べます。

再生の前に両キャラを記録開始時の位置に戻すので、記録したときと同じ距離で確認できます。`Lua Hotkey 1` でいつでも中止でき、そのときは保存されません。

**ジャンプの追加**

ダミーの行動に前・N・後ろのジャンプを追加しました。`Reversal/Counter Input Motion` の一覧、バックダッシュキャンセルの次に並びます。下を入れてから上を入れる形で、前後は上を入れるときに乗せます。

**Play Recording**

Recording タブの一番上から、現在のスロットをそのまま再生できます。再生ホットキーと同じ動作で、もう一度押すと止まります。

**アケコン1本でキャラクターセレクト**

1P キャラ → ステージ → 2P キャラまで、同じスティックで完結します。

**Loop Interval (Frames) (Before/After)**

ループ再生の合間に待ちを入れられます。待ちはダミーが動ける状態になってから数え始めるので、硬直の長さに左右されず一定の間隔になります。

### 改善

- スロットに記録した日時を表示します（メニューとウィザードの両方、24時間表記）。
- 1P と 2P が入れ替わっていても、左右を自動で反転して再生します。記録時にどちら側だったかを記録し、再生時に見比べています。
- ループ再生が、ダミーが動ける状態になるのを待ってから次の周を始めます。硬直中に次の入力が来て1周目が出ない、という状態が起きなくなります。
- 記録の自動終了を「技が終わってから2秒」に変更しました。レバーがニュートラルなだけでは終わらないので、長い技の途中で切れることがなくなります。
- メニューの配色を見やすくしました。
- ダウンリバーサルの無敵が通常の挙動になりました。コマ投げにセルフディレクションが付きます。メニュー操作のカクつきを解消しました。

### 修正

- **ガードキャンセルバックダッシュが失敗する問題**を修正しました。v11.3.1 で既知の不具合として挙げていたものです。弱・中・強すべてで安定します。
- **ウィザードの記録が途中で止まる問題**を修正しました。`Use Savestate Upon Recording` が有効なとき、ループ再生が1周終わる瞬間に読み込まれるセーブステートが、進行中の記録を打ち切っていました。
- キャラクターセレクトに戻った後も再生状態が続く問題を修正しました。
- 試合が始まるまで `Lua Hotkey 1` と `2` を受け付けないようにしました。

### 注意事項

- 設定ファイルは初回起動時に自動的に移行されます。保存済みの設定は同じ内容のまま引き継がれます。
- Display タブと Etc タブの初期値を見直しました。新規インストール時のみ適用され、既存の設定には影響しません。
