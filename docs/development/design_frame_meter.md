# Frame Meter の記録と表示 (2026-10-07)

`scripts/framemeter.lua` は tirsod 氏の [VSAV_FrameMeter](https://github.com/tirsod/VSAV_FrameMeter) を
取り込み、こちらで手を入れたもの (`VSAV_Training:` の印)。2026-10-06 から作者版と分岐してよい
(本人が作者に確認済み)。作者の更新は手で選んで取り込む。プレイヤー向けの説明は
`PLAYER_MANUAL` §11.6。ここは作りと根拠だけ。

## 原則

**基本の状態と付加情報を分けて記録し、付加情報の表示を切り替えても数値を変えない。**
数値 (Startup / Total / Recovery / Advantage、マスの数字) は基本の状態から数える。

## 記録 (`state_log`、1 Tick 1 列、P1 と P2 で同じ列)

| 番号 | 中身 | 書く所 |
|---|---|---|
| 1, 2 | 基本の状態 (0/1/nil 何もしていない、2 発生、3 攻撃判定、4 戻り、5 やられ・ガード、6 飛び道具、8 無敵、9 ジャンプ・ダッシュ) | `log_player_state` |
| 3, 4 | AG: 1 受付中 (自分の `$1AB` > 0)、2 成立 (相手の `$1B0` が 1..3) | 同上。成立は `read_pb_success` が毎 Tick 読む |
| 5 | P1 の入力 | `log_player_inputs` |
| 7 | その Tick が入った表示フレーム (120Hz の黒い点) | `log_player_state` |
| 8, 9 | リバーサルフレーム (free+0) | `read_reversal_ticks` |
| 10, 11 | 止まっていた (数えない) | `read_motion` |
| 12, 13 | 投げ無敵 (`$143`) | `log_player_state` |
| 14, 15 | 無敵 (ヒットボックス表示と同じ基準: `$134` / `$147` / `$11E` / `$145` かつ `$1A4` = 0 / やられ判定 `$94`-`$96` が全部 0) | `log_player_state` |

7 (投げ無敵) は状態から外した。以前は表示 ON のときだけ発生・攻撃判定・戻りを置き換え、数値を変えていた。

投げ (2026-10-08): 投げには攻撃判定が無い。ゲームが掴みを試すルーチンの入口 9 つ
(`0x02947E` ほか。VSAV_MEMORY_NOTES の「掴みを試すルーチン」) を Tick Data のフック
(tickDataVsav.lua) が両プレイヤー分数え、Frame Meter はその回数が増えた Tick と、相手が
投げられ状態 (`$05` = 0x06) に入った Tick を 3 (攻撃判定) にする。間合いの判定 `0x029406`
だけを呼ぶ箇所 (コマンドの成立条件) は数えない。同じアドレスに 2 つ目の registerexec は
置けない (後の登録が前を置き換える) ので、フックは Tick Data の分だけ。投げられている
(`$05` = 0x06) は 5。test_framemeter [4i]、test_tickdata_vsav。

## 記録する Tick

- 毎 Tick (`globals.truth.ticker`)。`read_motion` / `read_reversal_ticks` / `read_pb_success` は
  記録するかどうかに関係なく毎 Tick 走る (1 Tick しか出ない値を落とさないため)。
- **ヒットストップ:** `Show P1 Inputs` が ON なら全部記録する (入力の時期を見るため)。OFF なら、
  誰かがヒットストップ中 (`$5C`) で攻撃中のキャラが誰も動かなかった Tick を飛ばす。
- **動いた:** アニメが進んだ = `$20` (コマの残り) か `$1C` (コマ) が変わった。Tick Data と同じ。
  しゃがみ大K のようにヒットストップ中も動く技 (アニメ) がある。
- **止まっていた (10, 11):** 攻撃中のキャラは「誰かがヒットストップ中で、自分は動かなかった」。
  守る側は「自分の `$5C` が残っていた」(ガードに入るときのコマ替えは動いたことにしない)。
  攻撃側の `$5C` は守る側より 1 Tick 早く切れ、その Tick はまだ動かない。自分の `$5C` だけで
  見ると、入力表示 ON のときその Tick を数えた (近距離 LP の Total が 14)。
- 両者が 5 Tick 続けて何もしていないと止まる (`refresh_meter`)。**投げ無敵の間は止めない**
  (表示に関係なく)。

## 数える

`measure_player` は止まっていた Tick (10, 11) を飛ばす (数えず、連続も切らない)。マスの数字も同じ。
結果として:

- 攻撃側: 入力表示 OFF/ON で同じ値。デミトリ近距離 LP のガードで 4 / 13 / 7 (実機)。
- 守る側の黄の数字: Tick Data の Hitstun と一致 (近距離 LP のガードで 13、小 K のヒットで 14。実機)。

元からの動き (今回は変えていない): 最後の攻撃判定より後の青だけを戻りとして数えるので、
戻りの途中で次の攻撃を始めると `Recovery 0` になる。

## リバーサルフレーム (8, 9)

起き上がり・ガード後・やられ後・空中やられ復帰で、動ける最初の Tick (free+0)。この Tick に
始められるのは必殺技とガードだけ。

- 根拠: 必殺技は free-1 の入力で free+0 に出る (336 例)、ほかは free+0 の入力で free+1
  (`guardCancel.lua` の「WHAT IS ALLOWED ON THE FREE TICK」、起き上がり 373 回)。
- free-1 はゲームが `$04..$07 = 02 02 04 00` を書く (`0x024F0A`、続く `0x024F12` が必殺技の
  受付 `$174` を開く)。起き上がり 249/250、別の 2 バッチ 68+112 件で全種の復帰。署名が消えた
  最初の Tick に付ける。archive の毎 Tick のログでは 4358 回すべて 1 Tick だった (2026-10-07。
  ダウン 554、ガード 195、残りはやられ)。以前の「2 Tick 続くことがある (103 中 15)」は元の
  データをたどれなかった。
- キュービーの起き上がりは署名を書かず (0/21)、必殺技も free+1 から。印は付かない。
- 実機 (本人、2026-10-06/07): 4 場面、P1/P2、ノーマル速度で、印の Tick から必殺技、その次から
  ダッシュが出ることを確認。
- `dummyState.lua` の `p2_reversal_frame` (同じ値で「リバーサルが成立したか」を判定) は否定済みで、
  別の主張。ここは「動ける 1 Tick 前」のタイミングの実測だけを使う。

## 描画 (1 マス = 5x8、塗りは 3x6)

| 層 | 場所 | 条件 |
|---|---|---|
| 基本の状態 | マス全体の画像 | 常に (過去の区間で何もしていないマスは描かない) |
| 無敵 | 塗りの 4-6 行、白 (`#F2F2F2`、過去の区間は `#3C3C3C`) | 常に。投げ無敵の縞より優先 |
| 投げ無敵 | 塗りの 4-6 行、赤と白の縞 | `Show Throw Invulnerability` |
| 止まっていた | 塗りの 1-2 行、灰色 | 常に |
| リバーサルフレーム | 塗りの 1-2 行、マゼンタ (止まっていたより後に描く。黄色はやられのマスと同じ色で、リバーサル Tick に当たると消えた) | 常に |
| 120Hz の黒い点 | 境目の左右、塗りの 3 行目 | ターボで 2 Tick が同じ表示フレーム |
| AG 受付 | マスの左右の枠、黄色 | `Show P1 Inputs` |
| AG 成立 | マスの左右の枠、黄緑 | 常に |
| マスの数字 | 同じ状態が 5 マス以上続いたら | 常に (止まっていた Tick は数えない) |

過去の区間 (暗い色) は、印と縞を暗い色で描く。AG と数字は今の区間だけ (元から)。
