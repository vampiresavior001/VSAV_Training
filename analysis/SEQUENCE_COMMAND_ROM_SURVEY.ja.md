# 順押しコマンドのROM調査

2026-10-07 / `vsavj`（970519 Japan）。ソース基準：`7745eb19f15cc7961280e07adaa60c493585a107`。
既存のローカルROM＋MAME逆アセンブルを照合。静的解析であり、実機検証・本体修正は未実施。
全体設計：[COMMAND_TRAINER_DESIGN.ja.md](COMMAND_TRAINER_DESIGN.ja.md)。

## 結論

DI、LI、ミッドナイトプレジャーを先行対象とし、同じ認識器を使う順押し技を一群として対応する。
共通認識器`0x02A0C8`への入口10本を確認し、その入口への直接呼び出し11箇所を発見。
うち10箇所は技IDとEX状態の書き込みまで追跡できた。残る1箇所は状態内の特殊な呼び出し。
入口1本には今回の検索で直接参照が見つからない。未使用と断定しない。

技名はROMに文字列で格納された名称を抽出したものではない。
以下では、ROMから得た入力列と技IDを、charMoves.luaの入力列に付いた名称に照合している。
アナカリスのファラオ系は、ユーザー指定の信頼できる参照先
[Darkstalkers Frame Data：アナカリス EX必殺技](https://darkstalkers.web.fc2.com/savior/data-s/anakaris-s/anakaris-s-ex-move.html)
でも技名・入力列・消費ゲージを照合済み（2026-10-07）。
この照合により、既存の技ID一覧でSalvationとDecorationの名称が逆になっていると判断できる（後述）。

## 3. 共通の受理ルール

認識器`0x02A0C8–0x02A124`を確認した結果：

1. 入力テーブルwordの`$770F`マスク後の値と、+$1ACのwordを完全一致で比較する。
2. +$1ACはボタンだけでなく方向の立ち上がりも含む。+$1AE（離し）はここでは参照しない。
3. 最初の受理で+0が待機状態へ進み、各中間受理は`0x02A53A`で+1を2増やす。
4. 途中の不一致は待機を継続する。余分な入力が1度入っただけでは即終了しない。
5. 待機中はまず+4を減算。0なら入力比較より先にリセットする。
6. 最後は+1を増やさず、+0を0にしD0=1で戻る。タイムアウト側はD0=0。
7. 猶予は中間ステップの受理ごとに再設定される。固定の総入力時間制限として扱わない。

したがって、入力履歴だけを見て「コマンド列に似ていたら成功」と判定しない。
**呼び出し前の入力と、戻り後の進行／戻り値を対で採る。**
比較相手の入力wordには追加の方向・ボタンの立ち上がりも影響する。
保持中の余分な入力と、新しく同時に入った余分な入力は別物。

### 技別に可視化すると役立つ点

- DI／LI：2回目LPの押し直し、前方向の新しい入力変化。
- Midnight Pleasure：2回目MKの押し直し。離したこと自体は次段の受理ではない。
- Cryptic Needle：最後の前も新しい入力変化が必要。前保持のままでは最後に進まない。
- Tenraiha：2回目MPの押し直しに加え、最終入力がボタンではなく上方向。
- 7段のHK始動：5段固定のUI／配列にしない。途中の下入力と後半のボタン列を追えるようにする。
- すべて：同時入力で進まなかったTickと、その後の正しい入力で進んだTickを区別する。

## 4. 入力成立後の発動条件

全10技で、入力成立後にも別の条件分岐が存在する。
以下は確認できた直接の分岐であり、共通関数内部を含む全条件の自然言語化はまだ行っていない。

| 対象 | 主な確認箇所 |
|---|---|
| Midnight Pleasure | `030106`でゲージ2以上、`030110`で+$38=0、`030118`で共通状態判定 |
| Moment Slice | `031E94`で+$38=0、ゲージ、`031EA4`で共通状態判定 |
| DI／LI | ゲージと共通状態判定。先行設計書を参照 |
| Finishing Shower | `0398B8`で+$149、ゲージ、+$38、共通状態判定 |
| Cryptic Needle | `0399A4`からゲージ、+$38、共通状態判定 |
| ファラオ3経路 | 相手の+$1A0、自分の+$1B3、必要ゲージ、共通状態判定 |
| Tenraiha | `04B4AC`からゲージ、A5+$79BEが4以上、自分の+$14C、+$38、共通状態判定 |

共通状態判定は`0x02918A`。未解釈のフィールドを、特定の失敗原因名に推測で置き換えない。
トレーナーは「入力成立」「技発動」「入力成立・未発動」を分離する。
No meterなど具体的原因は、実際にその分岐で止まった証拠を得てから表示する。

## 5. 今回発見したデータの不整合

`scripts/charMoves.lua`では、入力列の名称と技ID一覧の名称が次のように交差している。

| 入力定義の名称 | 定義されている入力列 | ROMで到達する技ID | 現行の技ID一覧でその名称に付くID |
|---|---|---|---|
| P. Salvation | HK MP 下 MK HP | `$14` | `$1C` |
| Pharoah Decoration | HK MP LK 下 LP MK HP | `$1C` | `$14` |

**指定サイトとの照合により、入力定義の名称は正しく、技ID一覧の2名称が逆と判断する。**
サイトではサルベーションが5段・2ゲージ、デコレーションが7段・3ゲージ。
ROMから得た入力列・消費量と一致するため、正しい対応はSalvation=`$14`、Decoration=`$1C`。
修正時は技ID一覧のラベルと参照先を確認し、入力列を逆に交換しない。
保存キー・Action Steps・発動検出への影響を確認し、実機で各技の演出と技IDを検証する。
自動操作の入力列と発動検出で異なるIDを期待すると、技が出ているのに未発動と扱う恐れがある。
今回、既存データや保存済みAction Stepsは変更していない。

## 6. 通常技リストに混ぜない追加候補

### 同じDI入力を使う状態内処理

`0x035632`で`0x029E7A`を呼び、ブロックは+$360。
成立すると`0x03563A`で+$0Aに1を書く。周囲には+$3B4による呼び出しスキップもある。
通常の技IDとEX状態を書き込む経路ではないため、DIの別キャラ版などと命名しない。
初期トレーナーでは除外し、どの状態から到達するか・何の挙動を変えるかを追加解析する。

### 直接参照が見つからない入口

`0x029EAA` → テーブル`0x02A700` → `HK LP 下 LK HP`（5段）。
今回の絶対JSR/JMP・相対BRA/BSR検索では、この入口への参照は見つからなかった。
近くに技ID`$1E`の書き込み経路`0x03BB12`があるが、近接しているだけで対応付けない。
間接参照や別リビジョンの可能性は未確定。通常の対応済み技としてUIへ出さない。

## 7. 実装優先度と残る検証

1. DI／LI／Midnight Pleasure：共通の5段トレースを実測し、押し直しとゲージ差を確認。
2. Tenraiha／Cryptic Needle：最終方向入力と同じ方向の再入力を確認。
3. Moment Slice／Finishing Shower／Pharaoh Magicを追加。
4. アナカリスの2技は今回確定した名称・ID対応を反映し、7段表示と2／3ゲージ条件を実機確認して追加。

共通プローブは全10技分のプロフィールを持てる構成にする。
初期UIは選択式の1技表示。最終入力はボタン専用にせず方向も表現できるようにする。
保持／離し／立ち上がりとゲームの受理を別々に残す。誤入力の直後に進まなくても、
期限切れしていなければ、そのまま正しい入力で続けられたことを可視化する。

猶予値は前回と同じく未確定。逆アセンブルに見えるタイマー表と生ROMのビューが異なるため、
ROMの読み取り経路および実機の+4への設定値を確認するまで固定値や警告閾値を確定しない。
Normal／Turbo3、P1／P2、左右、向き反転、ヒットストップ、誤入力からの復帰、連続試行で確認する。
初回LPなどがそもそも受理されない場合も、詳細履歴には残す（成立した試行との集計は分ける）。

## 8. 再現方法と調査範囲

```sh
python analysis/extract_sequence_commands.py --code-dir /path/to/mame_code --rom-zip /path/to/vsavj.zip > analysis/sequence_command_evidence.json
```

抽出ツールはローカルの命令ビューとデータビューを使い分ける。
入口の分岐先、終端付き入力テーブル、直接参照、技ID書き込み、発動後RTSを確認する。
直接参照は復号済みバイトの偶数アドレスを検索するため、逆アセンブルの行境界の誤りにも対応する。
ただしデータを命令として拾う可能性があり、参照候補は周辺の命令列と照合した。
間接ジャンプを含む完全な制御フロー解析・実機動作確認ではない。
ROM本体と広範な逆アセンブルは成果物に含めていない。
