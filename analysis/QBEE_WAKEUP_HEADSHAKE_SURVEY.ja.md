# Q-Bee：起き上がり後の「首振り」追跡

更新日：2026-10-08。対象：vsavj、日本版プログラムROMと既存MAME逆アセンブル。

## 現在の結論（v11.7.23.1）

初期の静的解析に、開発側のターボ3実機ログによる調査が追加されている。
実測条件・回数・制約は[第9節](#qbee-measurements)を参照。

- 首振りセルに入るTickをTとすると、報告された74回すべてでTに状態が`$02000002`へ戻った。最も早い行動開始はT+1で、40回確認された。現行Meaty TimingはT+1を`Actionable +0t`として測る。
- セルの設定値は3だが、ターボ3の実測では、無入力時に同じセルが3～4 Tick続いた。設定値3を、そのまま実際の滞在Tick数とみなさない。
- 首振りの`cell+$0B=$FE`は通常の打撃判定経路を拒否する。DFではT+1に`$11E=1`となり、首振り側の属性からDF側の無敵フラグへの接続が報告されている。
- v11.7.23.1ではQ-Beeの起き上がりを`Actionable`で計測し、Frame Meterも首振りのうち`Actionable +0t`以降を白で示す。「起き上がりを測らない」「セル属性を読まない」という下記の記述は改修前の状況。

残る確認範囲：特殊な攻撃カテゴリや投げを含めた全行動・全状況の検証は完了していない。首振り中に打撃が成立しなかったログだけでは、間合いの影響を排除できない。ノーマル速度への一般化や、入力受付・接触の境界を処理順まで含めて確認する場合は追加計測が必要。

以下の第1～6節は**実測前の初期調査**、第7節は照合時点の記録、第8節は計測手順、第9節はその後の実測報告として残す。旧節の「未実測」「現行」は各調査時点を指し、現在の結論には上記と第9節を用いる。

## 初期調査の結論（実測前）

- 起き上がり末尾に、長さ3 Tickの共通セルが存在する。その場起き・移動起きの双方で同じスプライトを使う。ユーザーのいう「首振り」に対応すると考えられる。
- このセルは通常の打撃判定経路を拒否する属性 `cell+$0B=$FE` を持つ。単純な「無敵タイマー3」や「喰らい判定がすべて消える」という仕組みではない。
- セルに入った処理内で、通常の人間操作・ガード非移行経路は状態を `$02000002` に戻す。アニメーションは差し替えない。次回更新で通常行動の受付に進むため、首振りの終了を待つ必要はない。
- DFはその状態から発動可能。Q-BeeのDF開始処理は、新しいアニメーションを読み込む前に `$11E=1` を設定する。首振りの打撃無敵からDFの打撃無敵へ接続できる構造を確認した。
- 「首振りが3 Tick」と「Meaty Timingの+3が初めて当たる」は同義ではない。基準Tickとプレイヤー更新順の実測が必要。

## 1. 起き上がりから首振りへ

Q-Beeの起き上がりハンドラー：`0x04A6FA`。

| 経路 | 起き上がりアニメーション | 3 Tickセル | 次のセル |
| --- | --- | --- | --- |
| その場 | `$44` | `0x204C46` | `0x204C5E` |
| `$0A>0`の移動起き後 | `$46`（移動中は`$45`） | `0x204E2E` | `0x204E46` |
| `$0A<0`の移動起き後 | `$48`（移動中は`$47`） | `0x205016` | `0x20502E` |

3セルの主な値は共通：

| フィールド | 値 | 意味・根拠 |
| --- | --- | --- |
| `cell+$00` | `3` | アニメーションカウンターに読み込む長さ |
| `cell+$03` | `$FF` | プレイヤー`+$23`へ読み込み、起き上がり終了の分岐を通す |
| `cell+$04` | `0x20CC36` | 共通スプライト参照 |
| `cell+$08` | `6` | 喰らい判定マップID |
| `cell+$0B` | `$FE` | 通常の打撃判定経路では接触判定を拒否 |

次セルは3経路とも `cell+$0B=0`、判定マップIDは1になる。

`0x04A764` がアニメーションを更新し、`0x04A76A` が `+$23` の負値を検出する。
その後、投げ無敵 `+$143=5` を設定する（`0x04A776`）。これは首振り3 Tickとは別。
ガードへ移らない経路では `0x026E16` の変数リセットを呼び、
`0x04A7A0` で状態を `$02000002` にする。セルポインター `+$1C` は保持する。

例外：`+$3B4 != 0` なら `0x04A7AA` から `$02020400` へ進む。
したがって「Q-Beeは常に共通リバーサル状態を通らない」と無条件には書かない。

## 2. 無敵の根拠は攻撃判定側にある

打撃判定 `0x018000`：攻撃側=A6、防御側=A1。

- 攻撃側 `+$B3=0` の場合は `0x018040` へ進む。
- 防御側の現在セル `+$0B` が負値で、かつ `$FF` ではない場合、`0x018050` から不成立経路 `0x01822E` へ進む。
- 首振りの `$FE` はここで拒否される。実際の矩形重なり判定より前。

喰らい判定マップ6は `04 00 00 00`。頭部ID4は残っているため、
`+$94～+$96` の全ゼロ検出だけでは説明できない。
通常状態へ戻すリセット `0x026E16` は `+$11E` などをクリアするが、セル属性は保持する。

注意：攻撃側`+$B3`が正または負の経路は扱いが異なる。
この調査だけで「特殊な攻撃・追い打ち・投げを含めて全種類に無敵」と一般化しない。
投げは別系統の判定と`+$143`を確認すること。

## 3. 首振り中の行動とDF

状態`$02000002`は通常行動ループ `0x022642` へ進む。
必殺技受付、通常攻撃、方向入力による行動、ガードなどの共通分岐を利用する。
通常立ちアニメーションを読み込む初期化 `0x02261E` を通らず、首振りセルを保持している。
したがって「首振り専用の全行動キャンセル表」があるのではなく、通常受付へ先に復帰する構造。
各技・ジャンプ・ダッシュ・投げを個別に実測したわけではない。

DFへの経路：

1. `0x0223CA～0x0223D8`：ゲージ・入力認識後に共通DF受付`0x026FD2`を呼ぶ。
2. `0x026FEE～0x026FFC`：状態上位が`$0200`、`+$06<6`などを要求。`$02000002`は満たす。
3. `0x027000`：状態を`$02001600`へ変更。
4. 状態ディスパッチから`0x023258`、キャラクター別テーブル`0x0BF31A`へ。
   Q-Bee（CID `$0C`）のエントリーは`0x0493A8`。
5. 初期化で`0x0493D2`が`+$11E=1`を設定し、その後アニメーション`$53`を読み込む。
6. 打撃判定側`0x01806C～0x018070`は防御側`+$11E!=0`を拒否する。

このため首振りのセル属性を失う前に、DF側の無敵フラグを立てられる。
DFの後半では`0x049414`で`+$11E`を解除し、`0x049418`で`+$147=4`を設定する。
入力を出すTickごとの成功範囲・更新順ごとの接触結果は別途実測する。

## 4. Meaty Timingの基準を決める前に

入力なし、通常更新が進み、ほかの状態へ移らない場合の局所的な流れ：

| Q-Bee自身の更新 | 更新後のセルカウンター | 状態・属性 |
| --- | --- | --- |
| T：首振りセルに入る | 3 | `$FE`を保持し、通常行動状態へ戻る |
| T+1 | 2 | 通常行動を受け付ける。無入力なら首振り継続 |
| T+2 | 1 | 同上 |
| T+3 | 次セルの3 | 無入力なら`$FE`が外れる |

Tの起き上がりハンドラー内にはガード判定もあるため、入力次第でこの表とは異なる。
また、上表はQ-Bee自身の更新点を基準としており、相手の当たり判定時点とは区別する。

実装では次を同じ内部Tickログに記録して照合する：

- 両者の更新順・内部Tick番号と採取位相（更新前／後／接触時）。
- Q-Beeの`+$04`状態、`+$1C`セルポインター、`+$20`カウンター、`+$23`。
- セル`+$0B`、`+$94～+$96`、`+$11E`、`+$147`、`+$143`。
- 実際の入力、最初に行動へ遷移したTick、DF開始Tick、接触Tick。
- 現行Meaty Timingが採用した基準Tick。

その場起き・両移動起き、P1/P2、無入力／小技／ジャンプ／ダッシュ／DFを比較する。
「通常行動可能になった最初の更新」を0とするなら、セル移行Tを0とした場合と1 Tickずれる可能性がある。
現段階でQ-Beeだけ一律に3を加減する補正を入れない。
ユーザーの「+3付近の下段以外を狙う」という実戦知識は、この基準合わせと別に評価する。

## 5. Frame Meterへの含意

調査した`framemeter.lua`の`invulnerable`は、既知RAMフラグと喰らい判定全ゼロを確認するが、
セル`+$0B`による打撃の受け付け制限を見ていない。
首振りの打撃無敵を表示し損なう可能性があるため、上記ログで確認する。

`$FE`を単純に「打撃・投げとも完全無敵」の既存表示へ足すのは避ける。
攻撃カテゴリによる拒否、喰らい判定の欠如、投げ無敵は別の根拠なので、表示仕様と照合してから修正する。

## 6. 再解析時の注意と資料

- プログラムチップ順：`vm3j.03d, .04d, .05a, .06b, .07b, .08a, .09b, .10b`。
- 結合し各16bitをバイトスワップしたdata viewのSHA-256：

  https://docs.mamedev.org/techspecs/device_memory_interface.html

## 7. 照合（2026-10-08、手元の逆アセンブル `analysis/mame_code/`）

上の本文は受け取ったまま残し、照合した結果だけをここに書く。ROMのセルデータ（表1の`0x204C46`ほか）と、実機の動きは照合していない。

一致した点：

- `0x018040`～`0x018050`：攻撃側`+$B3`=0のとき、防御側の現在セル`+$0B`が負で`$FF`でなければ`0x01822E`（不成立）へ。
- `0x018026`～`0x01803E`：攻撃側`+$B3`が正のときは逆で、セル`+$0B`が`$FD`か`$FE`の相手にだけ判定を続け、それ以外は不成立。負なら`+$0B`を見ない。したがって`$FE`は「通常の打撃を受け付けない」属性で、`+$B3`が正・負の攻撃には当たり得る。全攻撃に対する無敵ではない。
- `0x018064`／`0x01806C`：防御側`+$147`、`+$11E`が0でなければ不成立。`0x018074`：セル`+$08`（判定マップID）が0なら不成立。
- `0x04A776`：`+$143=5`。`0x04A780`：`+$3B4`が0でなければ`0x04A7AA`で`$02020400`。0なら`0x027694`の結果で`0x027774`（ガード側）へ進むか、`0x026E16`を呼んで`0x04A7A0`で`$02000002`。
- `+$3B4`は`0x008A5C`で0に、`0x0090B2`・`0x009BF8`で1に書かれる。選択画面の実測では396行すべて0（VSAV_MEMORY_NOTES.md「決定が丸ごと無視される条件」）。対戦中の値は未実測。
- `0x026E16`は`+$11E`ほかを0にする。セル`+$0B`は書かない。
- `0x026FEE`：共通DF受付は状態の上位ワード`$0200`を要求する。`0x027000`で`$02001600`、`0x027014`で`+$143=$14`。Q-Beeの`0x0493D2`で`+$11E=1`、そのあと`0x0493D8`でアニメーション`$53`。

通常キャラとの比較：

- `0x024EA4`の処理はQ-Beeの起き上がりと同じアニメーションID（`$44`／`$45`／`$47`）を使い、`0x024F0A`でマーカー`$02020400`を書いて`+$174=5`とする（マーカーはVSAV_MEMORY_NOTES.md 5）。
- `0x025FBA`～に、Q-Beeの`0x04A770`～と同じ並びがある：`0x026058`の呼び出し、`+$143=5`、`+$174`に5を足す、`+$3B4`の判定（`0x025FE2`）。間に`+$186`（移動起き上がり）が立っていれば相手の`+$143=4`。どの状態・どのTickで走るかは未確認。
- Frame Meterの投げ無敵の縞は、リバーサルTickから5マス（画面で確認済み）。上の`+$143=5`と数は合うが、同じ書き込みかは未確認。マニュアルの「`+5t`が投げ無敵の境界、`+6t`は処理順に左右されない」とは矛盾しない。処理順の決まり方は未調査。
- 現行の`framemeter.lua`の無敵（`$134`／`$147`／`$11E`／`$145`と`$1A4`＝0／`$94`～`$96`が全部0）は、セル`+$0B`を読まない。首振りの判定マップ6は`$94`=4が残るため、首振り中は白にならないはず（実機で未確認）。

未確定（実測が要る）：

- 首振りセルに入るTick（表4のT）と、Meaty Timingの基準Tick・最初に通常行動を受け付けるTickの関係。Meaty Timingは現在、Q-Beeの起き上がりを測らない（マーカーが無いため）。
- セル`+$0B`が負になるセルが、首振り以外（ダウン中など）にどれだけあるか。Frame Meterに足すかどうかは、これを見てから決める。

## 8. 実機ログの取り方（2026-10-08）

`scripts/invulnLog.lua` が、`Analysis > Knockdown Logger` をONにしている間、試合中の各Tickを
`scripts/reversal_logs/invuln_log.jsonl` に書く（1行目は見出し、以降は1行が1プレイヤー・1 Tick）。
読む位相は見出しにある：Tickの時計（`rawStateService`のticker）で、各Tickのフレームスキップ読み出しの時点、
同じTickのTick Data・Meaty Timingの処理の**前**（Rxは後から登録した購読者を先に呼ぶ）。そのため`mt_rev`は
1 Tick前の状態で、実測でも1 Tick遅れて出た。

| 列 | 中身 |
|---|---|
| `tick` | Tickの時計の値。`mt_rev`と同じ単位 |
| `state` | `+$04～+$07`。`0x02000002`（通常行動へ戻った）、`0x02020400`（共通のリバーサル状態）、`0x02001600`（DF） |
| `cel` / `cnt` / `f23` | `+$1C`／`+$20`／`+$23`。Q-Beeは`cnt`が変わるだけでも1行になる |
| `c08` / `c0b` | 現在セルの`+$08`（喰らい判定マップ）と`+$0B`（首振りは`0xFE`のはず） |
| `hurt` / `f11e` / `f147` / `f134` / `f145` / `f1a4` / `f143` | 無敵・投げ無敵にかかわる値 |
| `hs` / `blk` / `air` / `f3b4` | `+$5C`（ヒットストップ）、`+$158`（ガード）、`+$38`（空中）、`+$3B4` |
| `btn` / `dir` | `+$122`（ボタン）、`+$125`（レバー、向きに対する相対） |
| `sb` / `sp` | ゲームが`0x018230`で確かめた、そのプレイヤーの本体／飛び道具による打撃の累計 |
| `mt_rev` | Meaty Timingが待っているリバーサルTick（Tick Data Sideの反対側、1 Tick前の時点）。なければ-1 |

手順（P1が攻め、P2がQ-Bee。開発ツリーで起動し、始める前に`python analysis/archive_logs.py`）：

1. `Analysis > Knockdown Logger = yes`、`Trainer > Tick Data = yes`（Tick Data Side = P1）。
2. P2をQ-Beeにし、足払いなどでダウンさせる。`Dummy > Wakeup`を`None`／`Towards`／`Away`の順に変えて各数回。
3. 起き上がりの行動を変えて、それぞれ数回：
   - 無入力（`Guard Action Type = None`）
   - 小技・必殺技（`Reversal - Specified`）
   - ジャンプ・ダッシュ・DF・投げ（`Reversal - Action Steps`で入力を作る）
4. P1の重ねを、早い・遅いの両方で試す（首振り中に当たらない・当たるの境目を見るため）。
5. P1とP2を入れ替え（Q-BeeをP1、`Tick Data Side = P2`。P2の攻めは記録の再生でよい）、2～4の一部をもう一度。処理順による違いを見るため。
6. 終わったら`invuln_log.jsonl`をそのまま渡す（`archive_logs.py`で保存してもよい）。

読むこと：首振りセル（`c0b`=`0xFE`）に入ったTick、`state`が`0x02000002`になったTick、最初の行動の`state`、
`sb`／`hs`が動いた（打撃が成立した）Tick、DFの`f11e`が立ったTickと首振りセルが外れたTickの前後関係、
P1／P2での違い。

## 9. 実測（2026-10-08、`reversal_logs_archive/v11.7.23_10/invuln_log.jsonl`）

開発ツリー、ターボ3。P1デミトリ／P2 Q-Bee、P1 Q-Bee／P2デミトリ。首振りのセル（`0x204C46`／`0x204E2E`／`0x205016`）に
入ったTickをTとする。74回（P2で57回、P1で17回）。Tickはログの`tick`（各Tickの途中で読んだ値）。

- **Tで**、74回すべて：状態`0x02000002`、`c0b`=`0xFE`、`c08`=6、`$143`=5、`$3B4`=0。
  マーカー`0x02020400`は通らない。`$3B4`は別の場面で1になることがあるが、Tでは0だった。
- **最初の行動はT+1**。T+1に状態が変わったのは40回：必殺技16、DF 9、歩き・しゃがみ6、ジャンプ4、通常技2、
  ダッシュ2、その他1。T+3とT+4に変わった回が1回ずつ（入力の時点はログから分からない）。Tに変わった回は無い。
  通常キャラでは必殺技がリバーサルTick、通常技がその次のTickからだが、Q-Beeは必殺技も通常技もT+1から出た。
- **無入力なら首振りのセルは3～4 Tick**（T～T+2、またはT～T+3）。ターボ3では4 Tickに1回、
  アニメーションのカウンターが進まないTickがあり（`tick`を4で割った余り1に6082回中5537回）、それが入ると4 Tick。
- **行動するとT+1でセルが替わり、`$FE`も外れる**。DFはT+1で`$11E`=1になる（Tの`$FE`からT+1の`$11E`へ途切れない）。
- `$143`はTの5からT+5の0まで、1 Tickに1ずつ減った。
- ジャンプ：T+1で跳び始め、T+4で`$38`≠0（4回、P1のQ-Bee）。
- **首振り中（`$FE`の間）に、Q-Beeへの打撃は一度も成立していない**（`0x018230`の数で0回）。ただし攻撃を重ねた回が少ない。
  1回（T=57194）は、別の起き上がり（T=56804）でT+8に当たったのと同じP1のセル（`0x12D8BA`）がT+1～T+3に出ていたが、
